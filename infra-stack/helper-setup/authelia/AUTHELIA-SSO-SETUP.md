# Authelia SSO Implementation Summary

## ✅ What Has Been Added

Your homelab infrastructure now includes **Authelia**, a centralized Single Sign-On (SSO) authentication system that protects all your services with a single login.

### New Components

#### 1. **Authelia Service** (`infra-stack/compose.yml`)

- Centralized authentication server
- Runs on port 9091
- Manages user credentials and sessions
- Supports TOTP (two-factor authentication)

#### 2. **Redis Service** (`infra-stack/compose.yml`)

- Session storage backend for Authelia
- Runs on port 6379 (internal only)
- Persists user sessions across restarts

#### 3. **Configuration Files** (`infra-stack/yaml-config/authelia/`)

- **authelia.yml** - Main configuration file
- **users_database.yml** - User accounts and passwords
- **README.md** - Quick reference guide
- **SETUP-GUIDE.md** - Comprehensive setup instructions
- **NGINX-CONFIG.md** - Nginx Proxy Manager integration guide
- **generate-secrets.bat/sh** - Secret generation scripts
- **generate-hash.bat/sh** - Password hash generation scripts

#### 4. **Environment Variables** (`infra-stack/.env.example`)

```env
AUTHELIA_JWT_SECRET=<auto-generated>
AUTHELIA_SESSION_SECRET=<auto-generated>
AUTHELIA_STORAGE_ENCRYPTION_KEY=<auto-generated>
AUTHELIA_NOTIFIER_SMTP_* # Optional email configuration
```

#### 5. **Updated Setup Script** (`setup.ps1`)

- Automatically copies Authelia configs to runtime directory
- Creates necessary directories
- Part of standard `npm run setup` flow

## 🚀 Quick Start

### Step 1: Generate Secrets

```powershell
cd infra-stack/yaml-config/authelia
./generate-secrets.bat
```

Or on Linux/Mac:

```bash
cd infra-stack/yaml-config/authelia
bash generate-secrets.sh
```

Copy the three generated values to `infra-stack/.env`:

```env
AUTHELIA_JWT_SECRET=<paste-here>
AUTHELIA_SESSION_SECRET=<paste-here>
AUTHELIA_STORAGE_ENCRYPTION_KEY=<paste-here>
```

### Step 2: Generate Password Hashes

For each user, generate a password hash:

```powershell
./generate-hash.bat "your-secure-password"
```

Or Linux/Mac:

```bash
bash generate-hash.sh "your-secure-password"
```

Update `infra-stack/yaml-config/authelia/users_database.yml` with the generated hashes.

### Step 3: Configure Domain

Edit `infra-stack/yaml-config/authelia/authelia.yml` and replace all instances of `yourdomain.com` with your actual domain.

### Step 4: Start Services

```bash
npm run setup
npm run start:all
```

### Step 5: Verify Authelia is Running

```bash
# Test the API
curl http://localhost:9091/api/state
# Should return: {"status":"ok"}
```

## 🔐 How It Works

```
User Requests Service (https://sonarr.yourdomain.com)
         ↓
   Nginx Proxy Manager
   (Forward Auth Check)
         ↓
    Send to Authelia
    (/api/verify)
         ↓
    ✓ Session Valid? OR Redirect to Login
         ↓
   User Logs In
   (Credentials verified)
         ↓
    Session Created (Redis)
         ↓
    Redirect Back to Service
         ↓
    Service Accessible
```

### authelia.yml

Main configuration file containing:

- Server settings (port 9091)

- Redis storage configuration
- User authentication backend (file-based)

- TOTP settings (2FA)
- Optional SMTP for password reset emails

User account database with:

- Username
- Display name

- Group memberships

### NGINX-CONFIG.md

Step-by-step guide for:

- Setting up forward auth in Nginx Proxy Manager
- Configuring each service
- Manual Nginx configuration (advanced)
- Troubleshooting
- Security best practices

## 🔑 User Management

### Add a New User

1. Edit `infra-stack/yaml-config/authelia/users_database.yml`
2. Generate password hash: `generate-hash.bat "password"`
3. Add entry:
   ```yaml
   username:
     displayname: "Display Name"
     password: "$argon2id$..."
     email: user@yourdomain.com
     groups:
       - users
   ```
4. Restart Authelia: `docker compose -f infra-stack/compose.yml restart authelia`

### Change a User's Password

1. Generate new hash: `generate-hash.bat "newpassword"`
2. Update the hash in users_database.yml
3. Restart Authelia

### Remove a User

1. Delete the user entry from users_database.yml
2. Restart Authelia

## 🎯 Access Control Policies

### bypass

No authentication required:

```yaml
policy: bypass
```

### one_factor

Password authentication only:

```yaml
policy: one_factor
```

### two_factor

Password + TOTP (2FA):

```yaml
policy: two_factor
```

Example in authelia.yml:

```yaml
- domain:
    - admin.yourdomain.com
  policy: two_factor

- domain:
    - sonarr.yourdomain.com
    - radarr.yourdomain.com
  policy: one_factor
```

## 📧 Email Configuration (Optional)

To enable password reset emails, configure SMTP in `.env`:

```env
AUTHELIA_NOTIFIER_SMTP_HOST=smtp.gmail.com
AUTHELIA_NOTIFIER_SMTP_PORT=587
AUTHELIA_NOTIFIER_SMTP_USERNAME=your-email@gmail.com
AUTHELIA_NOTIFIER_SMTP_PASSWORD=your-app-password
AUTHELIA_NOTIFIER_SMTP_SENDER=jerrod.sunderland@gmail.com
```

Then uncomment the SMTP section in authelia.yml.

## 🐛 Troubleshooting

### "Invalid credentials" error

- Verify password hash is correct: `generate-hash.bat "admin"`
- Check users_database.yml has valid YAML format
- Restart Authelia: `docker compose restart authelia`

### Can't login to services

- Verify Nginx Proxy Manager has Forward Auth configured
- Check Authelia logs: `docker compose logs authelia`
- Test Authelia directly: `curl http://localhost:9091/api/state`

### TOTP not working

- Ensure system time is synchronized (NTP)
- Clear browser cookies and retry
- Regenerate TOTP QR code in Authelia portal

### Session expires too quickly

- Increase inactivity timeout in authelia.yml
- Check Redis is running: `docker compose ps redis`
